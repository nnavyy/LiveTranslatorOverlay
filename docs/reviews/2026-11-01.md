# Re-review, fixes, and macOS port

1 November 2026, Asia/Jakarta. Baseline: v1.4.0 (`6b72b5e`). Follow-up: Windows v1.5.0 and a separate Mac developer preview for Apple Silicon and Intel.

## Assessment

The baseline builds and its 12 existing checks pass. It is **not yet justified to say everything is correct or that accuracy is generally verified**. Those checks cover particular regressions, not real speech, every language, device failures, or all interface paths.

Six new executable checks failed against the baseline. They pass after fixes; three more cover storage/history. The Mac preview implements manual text translation and session history. It does not yet implement system audio, screen OCR, or invisible overlay parity.

## Feedback

HTTP attempts now record Sending, accepted delivery becomes Sent, failures become Failed without clearing the form, and opening email composition is explicitly unconfirmed. Resolution still requires an explicit developer mapping; a new application version never proves that a report was fixed.

Remaining improvements:

- Retrying currently creates another report ID. Retry the existing entry and add idempotency before adopting a new backend.
- Let users preview/remove username and machine name from diagnostics. Optional contact email alone does not make a report anonymous.
- Add report deletion/retention controls. Descriptions, email addresses, and Windows API keys remain plaintext locally.
- Use separate refresh-error copy; localize stored category labels and resolution notes.
- A public status JSON and client-to-form submission are not an authenticated support inbox. Keep personal report contents out of the public feed.
- Damaged local history now surfaces an error instead of silently becoming an empty list. Add a recovery/import UI.

No mailbox message was sent; storage/delivery state changes were checked offline. A real end-to-end delivery/read/reply test still needs a deliberate test report.

## Translation history

Implemented: a 500-entry session cap, clear/export, save destination/overwrite prompt, listener cleanup, summary loading cleanup, summary cancellation on close, and capture exclusion after summary-window handles exist.

Still open:

- History remains session-only unless explicitly exported. Optional persistence, search, dated timestamps, and retention controls would help; avoid saving conversations by default.
- Auto-scroll always follows new text. Add pause-following for reading earlier entries.
- In-flight results can arrive after Clear. The Mac preview checks a history generation; equivalent handling across every Windows OCR/Deepgram path remains.
- Windows entry labels stay English under localized menus. Prefer structured entries rendered per locale.
- Summaries use only the last 15,000 characters and a capped output. Show that scope and keep AI summaries visibly distinct from the transcript.
- Store provider, source/target, and final/error state per entry; original-text fallback should not look like a confident translation.

## Accuracy and audio

Observed live text results:

| Source | Result |
|---|---|
| Do not open the door. | Jangan buka pintunya. |
| The price is 900 dollars, not 100 dollars. | Harganya 900 dolar, bukan 100 dolar. |
| I will arrive on November 1. | Saya akan tiba pada tanggal 1 November. |
| Saya tidak setuju. | I do not agree. |
| Matikan mikrofon saya. | Turn off my microphone. |
| ドアを開けないでください。 | Please don't open the door. |

The initial evaluator rejected the last correct result because it recognized “not” but not “don't.” The heuristic was corrected. That was an evaluation defect, not a translation failure. Full results matter more than calling six passes an accuracy score.

Remaining accuracy risks:

1. The resampler uses interpolation without a low-pass anti-aliasing filter and restarts fractional position per callback. Replace it with a stateful tested resampler; measure sample/timestamp continuity.
2. Deepgram sends are serialized now, but reconnect, queued-send backpressure, capture-start failure, Stop during connection, and rapid engine switching need integration coverage.
3. Audio overlap can duplicate words; the separate 20-second identical-transcript suppression can drop genuinely repeated dialogue. Prefer timestamp-aware overlap handling with confidence/voice evidence.
4. Pitch-based speaker labels are a heuristic, not reliable person identification or gender classification. Use neutral labels and validate overlapping speech.
5. Groq can fall back to Google, and failure can return original text. Introduce explicit success/fallback/error results and show the actual provider.
6. A language in the 34-entry translation catalog does not prove support in every speech model or installed OCR engine. Keep Auto limits and missing-pack/provider states visible.

Next quality gate: a versioned, consented audio corpus with reference transcripts, WER/CER, translated meaning/negation/numbers/names, end-of-speech latency, duplicated/dropped lines, and noisy/code-switched clips by model/language. Start with priority languages; do not infer universal quality from these smoke cases.

## Other Windows work

P1/P2: updater rollback/authenticity; encrypted keys and visible save errors; stale API-key validation responses; OCR coordinates on secondary/negative-origin/mixed-DPI displays; missing OCR packs; screenshots while affinity is temporarily disabled; device-loss recovery; lingering work after cancellation. Atomic writes improve storage safety but do not encrypt keys or eliminate every read/modify/write race in settings handlers.

P3: keyboard shortcuts/automation names, high-scaling layouts, consistent dark dialogs, language names, and notification preferences. Build/smoke checks do not establish these UX properties.

## macOS implementation and roadmap

WPF is Windows-only. Changing a runtime identifier cannot port WPF windows, WASAPI, Windows OCR, or Win32 hooks. [Microsoft WPF overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/).

The implementation extracts a plain .NET 10 shared library for translation, localization, settings, feedback, filters/cache, and history. A Windows-injected Japanese phonetic reader keeps the Windows API out of shared compilation. The existing WPF interface remains. A separate Avalonia preview supplies manual translation/history/export and an explicit issue link. Avalonia supports native ARM64 and x64 Mac builds. [Platform support](https://docs.avaloniaui.net/docs/supported-platforms), [Mac deployment](https://docs.avaloniaui.net/docs/deployment/macos).

| Capability | Status / next work |
|---|---|
| Text translation | Implemented preview; 34 choices, English UI initially; session-only Groq key. |
| History/export | Implemented, without automatic conversation persistence. |
| Feedback | Explicit GitHub issue form; Windows mailbox/history parity remains. |
| System/application audio | Native ScreenCaptureKit adapter, permission states, lifecycle, sample conversion, and latency tests. Capture requires authorization. [Apple ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit), [permission guide](https://support.apple.com/en-gb/guide/mac-help/mchl592e5686/mac). |
| Microphone | Native capture and permission path; denied/revoked access and routing tests. |
| Screen OCR | Apple Vision adapter, language discovery, Retina coordinates, region selection. Vision recognition is local. [Apple Vision](https://developer.apple.com/documentation/vision/recognizing-text-in-images). |
| Overlay | Native levels, click-through, Spaces/full-screen behaviour, accessibility tests. |
| Hidden from other recorders | **Do not promise Windows-equivalent invisibility.** Apple describes `NSWindow.SharingType.none` as a legacy value no longer used. Filtering our own stream does not control another recorder. Offer explicit window sharing/second-display workflows with clear limits. [Apple sharing types](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum). |
| Distribution | Separate native bundles and CI smoke checks; Developer ID signing/notarization and a signed Mac update feed remain. Preview is ad-hoc signed only. [Apple notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution). |

The bundle declares macOS 14 minimum; CI uses macOS 15 on each architecture. Native CI checks do not replace real-device permission, usability, Retina/multi-monitor, or notarized download/install tests. Mac artifacts use a separate prerelease so they cannot confuse older Windows updaters.

Next stages: native audio proof → permission/reconnect and ASR tests → Vision/Retina OCR → overlay/accessibility → feedback parity → signed/notarized beta. Keep Windows regressions running while each platform adapter is added.
